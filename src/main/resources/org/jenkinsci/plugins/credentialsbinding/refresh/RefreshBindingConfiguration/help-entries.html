Credentials listed here are re-resolved on every step of a withCredentials (or Pipeline environment{}) block, instead of being resolved once and cached for the whole block.

This is intended for credentials whose secret is short-lived and rotated on each read — for example a GitHub App installation token, which expires after about one hour. In a long-running build the cached token would go stale mid-block and later steps would fail with an expired token; refreshing per step makes every step see a fresh value.

All values a refreshed credential produces during the block (both the old and the newly rotated ones) stay masked in the console log and on the failure/exception surface.

Leave the list empty to keep the standard behavior: every credential is resolved once and cached, exactly as without this setting.
